| Option | Finding |

Precision: initialization calls MetaMask with pairing disabled; it does **not** itself request accounts or signatures on that path. It still depends on provider discovery/connectivity, and registers account/network listeners. Some listener paths request accounts or obtain a signer, so the broader initializer cannot be substituted for wallet-independent reads. [MetaMask source](https://github.com/hashgraph/asset-tokenization-studio/blob/be4f860e408ec5b1a24d12feb6f872aabff69319/packages/ats/sdk/src/app/service/wallet/metamask/MetamaskService.ts).

A useful narrowing: config requests accept a verified EVM address. Passing the Resolver address obtained by the existing Mirror/bytecode preflight avoids a second SDK Mirror lookup, whose 404 path retries up to ten times. This keeps the same pinned deployment and does not derive an address from its numeric ID. [Request validation](https://github.com/hashgraph/asset-tokenization-studio/blob/be4f860e408ec5b1a24d12feb6f872aabff69319/packages/ats/sdk/src/port/in/request/management/ResolveLatestConfigVersionRequest.ts), [address selection](https://github.com/hashgraph/asset-tokenization-studio/blob/be4f860e408ec5b1a24d12feb6f872aabff69319/packages/ats/sdk/src/app/service/contract/ContractService.ts), [Mirror retry](https://github.com/hashgraph/asset-tokenization-studio/blob/be4f860e408ec5b1a24d12feb6f872aabff69319/packages/ats/sdk/src/port/out/mirror/MirrorNodeAdapter.ts).
